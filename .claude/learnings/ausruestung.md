# Ausrüstung — eigene Erkenntnisse

- [2026-10-11] Deutsche Itemnamen: Adjektiv nach Genus deklinieren ("Gehärtetes Kurzschwert", "Runenverzierte Axt"); Suffixe "der Stärke / des Drachen" sind genusneutral. — **Warum:** Grammatikfehler fallen sofort auf.
- [2026-10-11] Leeres `baseType` + WEAPON = Altbestand → Dolch-Grafik. Neue Basistypen immer mit Grafik-Mapping anlegen. — **Warum:** alte Saves dürfen nicht ohne Grafik dastehen.
- [2026-10-11] Lange Button-Texte ("Verkaufen (252 Gold)") untereinander statt nebeneinander. — **Warum:** wurden abgeschnitten.
- [2026-10-11] Balance-Vorschlag offen: `statBudget`-Steigung 0.6→0.4 oder Waffenschaden 0.25→0.18 pro Stufe, falls Ausrüstung weniger dominant sein soll — nur zusammen mit Spielwelt-Neuabstimmung. — **Warum:** Spielwelt-Analyse.
- [2026-10-12] Itemname im UI immer allein oder unter einem Label ("Derzeit angelegt" klein darüber, Name in Seltenheitsfarbe darunter) statt in einer Satzschablone. — **Warum:** generierte Namen sind Nominativ ("Vergleich mit Robuste Lederstiefel" war falsch); zweizeilig kann der Name zudem farbig bleiben.
- [2026-10-12] Inventar-Füllstand nur abgeleitet: `Inventory.fill/freeSlots/fillFraction` (`InventoryFill.OK`/`NEARLY_FULL` ab ≤ 5 freien Plätzen/`FULL`). Test sichert `FULL` ⇔ `isFull` ⇔ nächster `tryAdd` verkauft automatisch. Kein GameState-Feld nötig. — **Warum:** Hinweis auf Auto-Verkauf ohne Vertragsänderung; Banner und Logik können nicht auseinanderlaufen.
- [2026-10-12] `InventoryCapacityBanner` steht oben im Tab (sofort sichtbar), "Zum Inventar" scrollt per `onGloballyPositioned { positionInParent().y }` → `scrollState.animateScrollTo(y)`. `AnimatedVisibility` in einer `spacedBy`-Column hinterlässt ausgeblendet keine Lücke; letzte Warnstufe per `LaunchedEffect` merken, damit der Ausblend-Übergang nicht leer/falsch rendert. — **Warum:** so funktionierte es ohne Layout-Sprünge.
- [2026-11-02] Verzaubern/Reroll: Basiswerte bleiben in `Item.bonus/damage*` gespeichert, der Verzauberungsbonus wird beim Lesen aufgeschlagen (`Item.effectiveBonus/effectiveDamageMin/Max` in `Enchanting.kt`). Jede neue Stelle, die Item-Werte liest (Kampf, Vergleich, Anzeige), muss die `effective*`-Variante nutzen. `Item.price` wächst mit der Stufe (+20 % Basispreis je Stufe), `Enchanting.basePrice` rechnet zurück, damit Kosten (Verzaubern 1,6^n, Reroll x2) nie auf dem verzauberten Preis aufbauen; Verkauf/Auto-Verkauf/Shop sehen den Aufschlag automatisch. — **Warum:** ein Preisfeld, keine Verkaufs-Sonderfälle in fremden Agenten.
- [2026-11-02] Kapazität nur über `Inventory.capacity(state)` (40 + `inventoryExtraSlots`, geklemmt); `Inventory.CAPACITY` ist nur noch die Basis. Erweiterungspreis (300 + 60 x Heldenstufe) x 3^Stufe. — **Warum:** vorher lasen Banner, Shop und OfflineProgress die Konstante direkt.
