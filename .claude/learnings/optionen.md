# Optionen — eigene Erkenntnisse

- [2026-10-11] Datei-Import akzeptiert `application/json`, `text/plain` und `application/octet-stream`. — **Warum:** manche Dateimanager melden .json als octet-stream.
- [2026-10-11] Eingabe auf ~1 MB begrenzen, Parsen wirft nie, sondern liefert Ergebnis/Fehler. — **Warum:** keine Abstürze, kein Überschreiben bei Müll.
- [2026-10-11] Android 12+ zeigt eigenen "eingefügt"-Hinweis neben unserer Snackbar — normal. — **Warum:** nicht als Bug melden.
- [2026-10-12] Import-Validierung deckt Charakter, Gold, Items (angelegt/Inventar/Shop-Angebote: Preis, Schaden ≥ 0 und min ≤ max, `itemLevel` 1..`ItemGenerator.MAX_ITEM_LEVEL`), `world` und `shop` ab. Neues Feld → `SaveField`-Eintrag + Label in `strings_options.xml` + Test; der `when` in `fieldLabel` erzwingt das Label. — **Warum:** neue Felder anderer Agenten fielen früher durchs Raster.
- [2026-10-12] Gültige Werte vor dem Ablehnen im Spielcode nachsehen, nicht raten: `heroHp` 0 = direkt nach Niederlage gespeichert, -1 = unbekannt; `damageMin/Max` 0..0 = Altbestand/Rüstung; `lastActiveEpochMillis` in der Zukunft = Uhr eines anderen Geräts (harmlos). — **Warum:** "≥ 1" für HP hätte echte Spielstände abgelehnt.
- [2026-10-12] Harmlose Unbekannte normalisieren + Hinweis im Bestätigungsdialog statt ablehnen: unbekannte `currentZoneId` → erstes Gebiet (wie `Zones.byId`), unbekannte Zonen-IDs in Fortschrittslisten bleiben erhalten (wirkungslos, gehen bei neuerer App-Version nicht verloren). Ablehnen nur bei Werten, die das Spiel nie erzeugt. — **Warum:** Spielstände neuerer App-Versionen/Tippfehler sollen importierbar bleiben, der Spieler sieht trotzdem, was passiert.
- [2026-10-12] Schutz vor falschen Ablehnungen: Property-Test über alle `ItemBaseTypes` × Seltenheiten × Stufen, `Shop.generateOffers` mit vielen Seeds und ein realistisch "durchgespielter" Spielstand aus echtem Domain-Code (Kills, Bosse, Drops bis Überlauf, Shop, Offline). Im Fixture nach jedem Gebiet ausrüsten — sonst ist das Inventar früh voll und es fehlen Slots. — **Warum:** fängt Formeländerungen anderer Agenten ab, die die Validierung verletzen würden.
- [2026-10-12] Konkrete Fehlermeldungen (Ort + Feld + Wert) sind mehrzeilig → Fehlerdialog statt Snackbar (4 s reichen nicht zum Lesen). — **Warum:** UX.
- [2026-10-12] Testdateien für die Emulator-Prüfung liegen in `app/src/test/resources/saves/` (per Test abgesichert): `adb push <datei> /sdcard/Download/` → Optionen → "Aus Datei laden". — **Warum:** Clipboard per adb ist unzuverlässig, Dateien über SAF gehen immer.
- [2026-10-13] Geräte-Einstellungen (Ton) NICHT in `GameState` legen, sondern separat (`ui/options/GameSettings`, SharedPreferences hinter `SettingsStore`-Interface). — **Warum:** Spielstand-Import würde sonst die Toneinstellung überschreiben; Interface macht es JVM-testbar ohne Robolectric. Audio-Code soll `GameSettings.get(ctx).soundEnabled` prüfen.
- [2026-10-25] Spenden-Button (Stripe-Link `DonateLink.URL`) wurde auf ausdrücklichen User-Wunsch wieder eingebaut, trotz Play-Payments-Risiko (externer Zahlungslink). Datenschutzerklärung (`docs/index.html` + In-App-Kurzfassung) nennt ihn. Console: Finanzfunktionen = "keine" (Spende ist kein Banking/Wallet/Transfer); wird die App erneut wegen Organisationskonto/Payments abgelehnt, ist der Button die erste Ursache.
- [2026-10-28] Neue Geräte-Einstellung (z. B. `autoBoss`): Flow + Setter in `GameSettings`, Switch-Karte in `OptionsScreen`, Test mit `FakeStore` (Default, Persistenz, Flow). Sie liegt nicht in `GameState` — Import/Export und `SaveTransfer` fassen sie nie an, kein Validierungsfeld nötig.
- [2026-10-28] `SettingsStore` hat nur Boolean/String: Long-Werte (Zeitstempel) als String speichern statt das Interface zu erweitern (Fake-Stores in fremden Tests würden brechen). Sicherungs-Erinnerung: reine Regeln in `BackupReminder` (Zeit als Parameter, Zukunfts-Zeitstempel = frisch/erlaubt wegen Geräteuhr), Start-Dialog `BackupReminderDialog` hängt in `MainActivity` (nicht in geteiltem `MainScreen`). Export-Datum wird bei Datei- und Zwischenablage-Export gesetzt. Datenschutztext unverändert nötig: nur lokales Datum, nichts übertragen.
